# Учёт оплат учебного центра

Тестовое задание Ecomdev: предметы и группы, ученики с автоматическим кодом, оплаты, отчёт «должники за месяц»,
мобильная веб-страница и Telegram-бот.

**Стек:** Node.js + TypeScript, Fastify, Prisma, SQLite, zod · React + Vite · grammY · Vitest · Docker.

## Запуск с нуля

Нужен Node.js 20+ (проверено на 24) и git.

```bash
git clone https://github.com/Abdulloh1623/ecomdev-payments.git
cd ecomdev-payments
cp server/.env.example server/.env      # Windows: copy server\.env.example server\.env
npm run setup                           # зависимости + миграции + демо-данные
npm run dev                             # API :3000 и веб :5173 с hot reload
```

- Веб-страница: http://localhost:5173
- API: http://localhost:3000, Swagger UI: http://localhost:3000/docs

Одним процессом, как в продакшене (сервер сам раздаёт собранный фронтенд):

```bash
npm run build
npm start                               # веб + API на http://localhost:3000
```

### Docker

```bash
docker compose up --build               # http://localhost:3000
```

## Модель данных

```
Subject (предмет) ──< Group (группа: преподаватель, расписание) ──< GroupPrice (история цен)
                              │
Student (ученик, код ST-0001) ──< Enrollment (участие: joinedOn … leftOn) >── Group
        └──< Payment (оплата: сумма, дата)
```

- **Код ученика** `ST-0001` присваивается автоматически — он выводится из id, поэтому уникален.
  В API и боте можно указывать и код, и просто id.
- Ученик при создании записывается в **одну или несколько** существующих групп.
- Перевод между группами не стирает историю: старое участие закрывается датой перевода, новое начинается с неё.

### Соответствие ТЗ

В ТЗ у ученика есть поля «группа» и «месячная сумма». После доработки:
- **группа** — не текстовое поле, а связь с одной или несколькими группами (`groupIds`);
- **месячная сумма** — не вводится вручную, а считается: сумма цен групп ученика (`monthlyFee` в ответе API).

## API

Все ошибки в одном формате: `{ "error": { "code", "message", "details?" } }`. Полная схема — в Swagger (`/docs`).

| Метод | Путь | Описание |
|---|---|---|
| GET, POST | `/subjects` | Предметы: список, создание `{ name }` |
| GET, PATCH, DELETE | `/subjects/:id` | Предмет; удалить можно только без групп (иначе 409) |
| GET | `/groups?subjectId=` | Группы с текущей ценой и числом учеников |
| POST | `/groups` | `{ subjectId, name, monthlyPrice, teacher?, schedule? }` |
| GET | `/groups/:id` | Группа: история цен и текущие ученики |
| PATCH | `/groups/:id` | Любые поля; `monthlyPrice` + `priceFrom: "YYYY-MM"` — новая цена с месяца (по умолчанию текущий) |
| DELETE | `/groups/:id` | Только без учеников (иначе 409) |
| GET | `/students?groupId=&subjectId=` | Ученики с группами и месячной суммой |
| POST | `/students` | `{ name, phone, groupIds: [1, 3], joinedOn? }` → 201 |
| GET | `/students/:id` | По id или коду: `/students/ST-0002` |
| PATCH | `/students/:id` | `{ name?, phone?, groupIds?, effectiveOn? }` — `groupIds` задаёт новый полный список групп |
| DELETE | `/students/:id` | Мягкое удаление: выбывает из групп сегодняшним днём → 204 |
| POST | `/payments` | `{ studentId, amount, date? }` → 201, `date` по умолчанию — сегодня |
| GET | `/students/:id/payments` | Оплаты ученика, новые сверху (то же: `GET /payments?studentId=`) |
| GET | `/debtors?month=YYYY-MM` | Должники за месяц; без `month` — текущий |

```bash
curl -X POST localhost:3000/subjects -H 'content-type: application/json' -d '{"name":"Английский язык"}'
curl -X POST localhost:3000/groups -H 'content-type: application/json' \
  -d '{"subjectId":1,"name":"A1 утро","monthlyPrice":500000,"teacher":"Дилноза","schedule":"Пн/Ср/Пт 09:00"}'
curl -X POST localhost:3000/students -H 'content-type: application/json' \
  -d '{"name":"Азиз Каримов","phone":"+998901234567","groupIds":[1]}'
curl -X POST localhost:3000/payments -H 'content-type: application/json' \
  -d '{"studentId":1,"amount":200000,"date":"2026-10-05"}'
curl 'localhost:3000/debtors?month=2026-10'
```

Ответ `/debtors`:

```json
{
  "month": "2026-10", "count": 1, "totalDebt": 300000,
  "debtors": [{
    "id": 1, "code": "ST-0001", "name": "Азиз Каримов", "phone": "+998901234567",
    "due": 500000, "paid": 200000, "debt": 300000, "deleted": false,
    "groups": [{ "groupId": 1, "name": "A1 утро", "subjectName": "Английский язык",
                 "price": 500000, "days": 31, "charge": 500000 }]
  }]
}
```

### Как считаются должники

- **Начислено за месяц** (`due`) — сумма по группам, в которых ученик состоял в этом месяце:
  `round(цена группы в этом месяце × дней в группе / дней в месяце)`.
  Полный месяц — ровно цена; пришёл 15-го или ушёл в середине месяца — пропорционально дням.
  Дни участия — интервал `[joinedOn, leftOn)`: день прихода оплачивается, день ухода — нет.
- **Цена по истории:** цена действует с месяца `fromMonth` до следующего изменения, самая ранняя — и для всех
  месяцев до неё. Изменение цены не пересчитывает прошлые месяцы.
- **Оплачено** (`paid`) — оплаты, у которых дата в этом месяце. Переплата на другие месяцы не переносится.
- **Долг** `debt = due − paid`; в отчёт попадают только `debt > 0`, в том числе те, кто не платил вовсе.
  Ученик без групп ничего не должен.
- Удалённый ученик остаётся в отчётах за месяцы, когда он учился (флаг `deleted: true`).
- Сортировка — по убыванию долга. «Текущий месяц» и «сегодня» — в часовом поясе `APP_TIMEZONE` (по умолчанию `Asia/Tashkent`).

### Прочие решения

- **Мягкое удаление** ученика, группы и предмета: история участия и оплат сохраняется.
  Вносить оплату удалённому ученику нельзя (404).
- **Деньги** — целые числа (без копеек/тийинов), от 1 до 1 000 000 000.
- **Валидация:** телефон — 7–20 символов из цифр, пробелов, `+ - ( )`; даты проверяются на существование
  (`2026-02-30` → 400); названия предметов и групп внутри предмета уникальны без учёта регистра (409).

## Веб-страница

Вкладки внизу экрана, рассчитаны на телефон:

- **Должники** — переключение месяцев, итоги, начисления по группам (с днями, если месяц неполный),
  прогресс оплаты, звонок по нажатию на телефон. «Внести оплату» открывает форму с учеником и остатком долга.
- **Оплата** — поиск ученика по имени, коду или группе, сумма, дата, история оплат ученика.
- **Ученики** — создание и изменение с выбором групп (по предметам, с итогом в месяц), удаление.
- **Группы** — предметы и их группы: создание, изменение (в т. ч. цены), удаление пустых.

## Telegram-бот

1. Создайте бота у [@BotFather](https://t.me/BotFather) и впишите токен в `server/.env` → `TELEGRAM_BOT_TOKEN`.
2. Запустите сервер и напишите боту `/start` — он ответит вашим Telegram ID.
3. Впишите ID в `ADMIN_IDS` (несколько — через запятую) и перезапустите сервер.

Команды: `/debt` — должники текущего месяца с кодами и группами; `/pay <код ученика> <сумма>` — оплата
сегодняшним числом (`/pay ST-0003 500000`, можно `/pay 3 500 000`). Бот отвечает, сколько осталось заплатить за месяц.

Бот работает в том же процессе, что и API (long polling). Без токена он просто не запускается, API работает.
Доступ — только для `ADMIN_IDS`, потому что бот показывает телефоны и меняет данные.

```
  src/
    routes/        HTTP-слой (Fastify + zod-схемы)

    bot.ts         Telegram-бот
    app.ts         сборка приложения, формат ошибок, Swagger, раздача фронтенда
  test/            Vitest: API через app.inject, отчёт должников, юнит-тесты
web/src/           React: вкладки должников, оплаты, учеников, групп
```

## Известные ограничения

- Дату перевода между группами (`effectiveOn`) и дату прихода (`joinedOn`) можно задать через API;
  в веб-форме используется сегодняшняя дата.
- `npm audit` показывает уязвимость в `deepmerge-ts` внутри CLI Prisma 6 (dev-зависимость, в рантайм не попадает).
  Исправление — переход на Prisma 7 с новой конфигурацией, это сознательно отложено.
